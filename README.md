# Trondheim Historical Map

Interactive web map of Trondheim's development from **1700 to the present**. Buildings,
roads, and water features carry temporal attributes (`sd` = start year, `ed` = end year),
so a year slider filters the map to show the city as it was at any point in time.

Features are assembled from OpenStreetMap, Norwegian registries (SEFRAK, Matrikkelen,
Byantikvaren, FINN), manual edits, and ML extraction (a U-Net segmentation model) from
georeferenced historical Kartverket maps.

> **Status:** Working prototype, actively developed. This is a personal project, not a
> hosted product. Some data sources and the ML pipeline are partial — see
> [`docs/tech/IMPLEMENTATION_STATUS.md`](docs/tech/IMPLEMENTATION_STATUS.md) for the honest

## Quick start

```bash
# Full stack: frontend + backend + data serving, all behind nginx on :8080
docker compose up -d
open http://localhost:8080

docker compose restart   # after editing backend/ or nginx.conf (volumes are mounted, no rebuild)
docker compose down
```

**Frontend-only dev server** (no backend):

```bash
make serve   # npx serve on :8080
```

> ⚠️ Do **not** use `python3 -m http.server` — PMTiles require HTTP range requests, which
> it does not support, and the map will silently fail to load.

**Reach the backend** through nginx at `http://localhost:8080/api/...` — port 5000 is not
published to the host. See [`AGENTS.md` §1](AGENTS.md) for all ports.

## Data pipeline

Always run from the repo root with `PYTHONPATH=scripts`:

```bash
PYTHONPATH=scripts python3 scripts/pipeline.py --stage all      # ingest → normalize → merge → export
PYTHONPATH=scripts python3 scripts/pipeline.py --stage export   # regenerate frontend data only
PYTHONPATH=scripts python3 scripts/pipeline.py --list           # sources + stage status
```

Flow: `data/sources/{src}/raw → normalize → data/merged/ → export → data/export/`
(GeoJSON + PMTiles via [tippecanoe](https://github.com/felt/tippecanoe)). Details in
[`AGENTS.md` §6](AGENTS.md) and [`docs/tech/DATA_PIPELINE_ARCHITECTURE.md`](docs/tech/DATA_PIPELINE_ARCHITECTURE.md).

## Machine learning

U-Net semantic segmentation (`segmentation-models-pytorch`) extracts buildings/roads/water
from historical maps. Training/inference/vectorization live in `ml/`:

```bash
python ml/train.py --config ml/config.yaml
python ml/predict.py --checkpoint models/checkpoints/best_model.pth --input image.png --output mask.png
python ml/vectorize.py --input mask.png --output features.geojson --bounds "10.38,63.42,10.42,63.44"
```

See [`AGENTS.md` §7](AGENTS.md) and [`docs/tech/methodology.md`](docs/tech/methodology.md).

## Tech stack

- **Frontend:** MapLibre GL JS 4 + PMTiles, vanilla ES6 (no framework, no build step)
- **Backend:** FastAPI (Python 3.12), async subprocess job queue
- **Pipeline:** Python + tippecanoe (vector tiles), GDAL (raster tiles / georeferencing)
- **ML:** PyTorch, segmentation-models-pytorch (U-Net), Albumentations
- **Serving:** Docker Compose + nginx
